# BrotatoLike

> Unity Top-Down 动作生存游戏 Demo — 类《Brotato》玩法，支持单人 / 本地同屏双人 / 联机双人（联机进行中）
> **目标岗位**: 游戏客户端开发实习生 / Unity 客户端开发实习生

## 快速开始

### 环境要求

| 工具 | 版本 |
|------|------|
| Unity | 6.5 (6000.5.4f1) |
| 输入系统 | Input System Package |
| 网络 | Netcode for GameObjects 2.13.1（联机模式需要） |

### 打开项目

```bash
git clone <repo-url>
# 用 Unity Hub 打开项目文件夹
# 打开 Assets/Scenes/SampleScene.unity → 点击 Play
```

### 操作方式

| 操作 | 单人 / 玩家 1 | 玩家 2（本地双人） |
|------|--------------|-------------------|
| 移动 | WASD | 方向键 |
| 瞄准 | 鼠标 | 自动朝向移动方向 |
| 暂停 / 继续 | ESC | - |
| 选择升级选项 | 鼠标点击 | - |

主菜单提供 3 个模式 Toggle：**单人 / 本地双人 / 联机双人**（联机模式进入后弹出创建/加入房间面板）。

### 游戏规则

1. 在圆形竞技场内生存，抵御无限波次的敌人
2. 武器**自动攻击**范围内的敌人
3. 击杀敌人掉落经验球，靠近自动拾取
4. 升级时弹出 3 选 1 强化；**升级不再暂停游戏**——升级者本人暂停操作并获得 3 秒无敌，双人模式下两人互不干扰
5. 死亡后显示结算：存活波次、等级、击杀数、存活时间
6. 目标：活得越久越好

## 功能特性

### 游戏系统

| 系统 | 说明 |
|------|------|
| **3 种武器** | 魔法弹（单目标跟踪）、火焰喷射（扇形范围）、飞弹环绕（被动碰撞） |
| **5 种敌人** | 史莱姆、骷髅、蝙蝠、暗影法师（远程）、幽灵（冲刺） |

| **联机双人（进行中）** | NGO Host/Client 骨架：本地/远端控制权隔离、NetworkTransform 同步远端位置、动态联机面板（UTP 配置 IP） |
| **结算统计** | 波次、等级、击杀数、存活时间 |
| **暂停菜单** | 继续 / 重新开始 / 返回主菜单 |
| **地图选择** | 预留接口，后续可扩展多地图 |

## 技术架构

### 整体设计

```
数据层 (ScriptableObject)
    ↓
逻辑层 (MonoBehaviour Components)
    ↓
表现层 (UI / VFX / 伤害数字)
```

### 核心架构模式

| 模式 | 应用 |
|------|------|
| **数据驱动** | 武器、敌人、升级全部通过 ScriptableObject 配置，数值调整无需改代码 |
| **Component 分离** | 玩家属性独立为 `PlayerStatsComponent`，武器和敌人逻辑各自内聚 |
| **状态机** | `GameManager.EGameState` 统一管理 5 种游戏状态（主菜单/游戏中/暂停/升级/结算） |
| **事件驱动 UI** | HUD 通过事件监听（`OnHPChanged` / `OnXPChanged` / `OnPlayerRegistered`），不轮询 |
| **抽象基类** | `Weapon` 基类提供通用流程，子类只需实现 `Fire()` |
| **输入抽象** | `IInputProvider` 接口统一键鼠 / 方向键 / 网络输入，玩家 2 与联机玩家复用同一套移动逻辑 |
| **网络分层** | `PlayerNetworkBehaviour` 通过 `IsOwner` 区分本地/远端：本地读输入可战斗，远端由 NetworkTransform 驱动、不参与本地索敌与武器攻击（战斗同步规划移交服务器权威） |

### 性能优化

| 优化 | 说明 |
|------|------|
| **敌人注册表** | 敌人出生/死亡时 O(1) 注册注销，索敌遍历注册表 + 缓存目标（有效期内免扫描，失效后 0.2s 限频重扫），替代 `FindObjectsByType` 全场景扫描，查询零 GC 分配 |
| **对象池** | 敌人、子弹、经验球、火焰粒子四类高频对象全部池化复用，消除运行时 Instantiate/Destroy |
| **蓄水池采样** | 随机索敌单遍均匀采样，避免收集列表分配 |
| **平方距离比较** | 索敌/拾取用 `sqrMagnitude` 替代 `Vector3.Distance`，省去开方 |
| **视口四边形刷怪** | 以相机视角中心为圆心：屏幕四角视线与玩家水平面的交点构成可视四边形，各方向刷怪下限 = 穿出屏幕距离 + 余量（恒在屏幕外刷出），上限 = 地图圆边界，360° 均匀来袭且环带随玩家自动移动 |

### 项目结构

```
Assets/
├── Scripts/
│   ├── GameTypes.cs              ← 核心枚举定义
│   ├── Definitions/              ← ScriptableObject 定义
│   ├── Game/                     ← 游戏管理器
│   │   ├── GameManager.cs        ← 全局状态机 + 多玩家注册 + 升级选项生成
│   │   ├── WaveManager.cs        ← 波次推进
│   │   ├── MonsterSpawner.cs     ← 怪物生成（视口四边形环形带）
│   │   ├── EnemyRegistry.cs      ← 活敌人注册表（O(1) 查询）
│   │   └── ObjectPool.cs         ← 通用对象池 + 敌人分池
│   ├── Player/                   ← 玩家系统
│   │   ├── PlayerController.cs   ← 移动/武器/升级状态
│   │   ├── PlayerStatsComponent.cs ← 属性与升级生效
│   │   ├── IInputProvider.cs     ← 输入抽象接口
│   │   ├── KeyboardMouseInputProvider.cs ← 玩家 1 输入源（WASD + 鼠标）
│   │   ├── ArrowsInputProvider.cs ← 玩家 2 输入源（方向键）
│   │   ├── PlayerStatusBar.cs    ← 玩家 2 头顶血条
│   │   └── PlayerNetworkBehaviour.cs ← 联机本地/远端控制权隔离
│   ├── Weapons/                  ← 武器系统（基类 + 3 种实现）
│   ├── Projectiles/              ← 投射物
│   ├── Enemies/                  ← 敌人系统（基类 + 5 种实现）
│   └── UI/                       ← UI 界面（7 个界面脚本 + 伤害飘字）
├── Data/                         ← ScriptableObject 资产
│   ├── Weapons/                  ← 3 个武器配置
│   ├── Enemies/                  ← 5 个敌人配置
│   └── Upgrades/                 ← 11 个升级选项配置（9 属性 + 2 武器）
└── Scenes/
    └── SampleScene.unity         ← 游戏场景（含 Canvas + 所有 UI）
```

### 游戏状态机

```
MainMenu ──"开始游戏"──→ Playing ──"ESC"──→ Paused
   ↑                       │   ↑              │
   │    "返回主菜单"        │   └──"ESC"───────┘
   │                       │   "继续"
   │                       ├── LevelUp (升级弹出，时间不暂停，升级者 3 秒无敌)
   │                       ├── 死亡 ──→ GameOver
   │                       │              │
   └───────"返回主菜单" ←──┘              │
                                           ├──"再来一次"──→ Playing
                                           └──"返回主菜单"──→ MainMenu
```

联机模式：主菜单 → "开始游戏"（联机）→ 联机面板（创建/加入）→ Host/Client 连接后各自生成网络玩家 → Playing。

## 面试展示亮点

| 亮点 | 说明 |
|------|------|
| **数据驱动架构** | 所有游戏数值走 ScriptableObject，策划可独立调参 |
| **Component 分离设计** | `PlayerStatsComponent` 独立负责属性，职责单一 |

| **完整游戏流程** | 主菜单 → 游戏 → 暂停 → 升级 → 结算 → 重新开始，闭环完整 |

| **联机分层设计** | 本地/远端控制权隔离，战斗同步规划移交服务器权威，多人在线能力分阶段演进 |
